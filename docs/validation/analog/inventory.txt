!! REQUIRED SIMULATOR SETTING: the container's ngspice reads the HOME .spiceinit (shown above) which sets
!!   set ngbehavior=hsa   (plus ng_nomodcheck, num_threads=4, enable_noisy_r).
!! The models-dir .spiceinit is empty (0 bytes). Any other ngspice, including our WASM build, must set
!! ngbehavior=hsa to reproduce these numbers. Without it, results are not comparable to this file.

Typical corner lines for a deck:
  .include <models>/design.ngspice
  .lib <models>/sm141064.ngspice typical
('typical' (lines 105-137 of sm141064.ngspice, checked in the container) pulls in all MOS sections for the corner:
 nfet_03v3_t, pfet_03v3_t, nfet_06v0_t, pfet_06v0_t, nfet_06v0_nvt_t, noise_corner and fets_mm, plus the 06v0 params.
 Do NOT add those again (duplicate .subckt/.model errors). Diodes, BJTs and resistors are NOT included: add
 .LIB diode_typical / bjt_typical / res_typical when a deck uses them; caps: .LIB moscap_typical and
 .LIB mimcap_typical (sm141064_mim.ngspice cap_mim_new). See section list above.)

OSDI / code models: NOT needed. The grep count for osdi/codemodel/pre_osdi/.hdl/.load is 0 in all four
model files. All MOS models are .model ... nmos/pmos level=54 (BSIM4 v4.5, built into ngspice). The
subcircuit wrappers use only behavioural params (agauss, ternary) that ngspice's parser handles.
The container's ngspice has OSDI files in its lib dir (bsimcmg.osdi etc.) but the gf180 models do not use them.
=> a WASM ngspice build with BSIM4 (default) and no dlopen/XSPICE-codemodels is enough.

Instance syntax: X<name> d g s b nfet_03v3 W=.. L=.. [nf= m=]  (4 terminals, subckt nfet_03v3 / pfet_03v3,
which wraps one BSIM4 device named m0). Minimum L = 0.28u (lmin 2.8e-7), minimum W = 0.22u.
Probe path of a device in a subckt instance: @m.<xinst>.m0[param], lowercase; nested:
@m.xota.xm1.m0[vth] (instance xota containing xm1). Params available: vth vdsat gm gds gmbs id vgs vds.
Sign conventions (checked at nfet Vgs=1.0 Vds=1.65 and pfet Vsg=1.0 Vsd=3.3): probes are normalised to
the device type, so for the PMOS vth, vdsat, vgs, vds and id are all POSITIVE (vgs=+1.0, vds=+3.3,
vth=+0.681, vdsat=+0.324, gm=+47.7u, id=+8.99u). So region check is the same for both types:
off if vgs<vth; triode if vds<vdsat; else sat. (These are the normalised @m probes above. The raw i(Vd) of
the pmos_idvg deck is a different thing: positive i(Vd) means current flows into the + terminal of source Vd,
i.e. from the circuit node into Vd. Example: +51.25uA at Vsg=1.65, Vsd=1.65.)
Note: with -b the nested .lib path works with absolute paths; decks use /foss/pdks/gf180mcuD/libs.tech/ngspice/.
